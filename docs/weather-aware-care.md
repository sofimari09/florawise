# Погодно-залежний догляд FloraWise

## Архітектура та джерело

Використано наявні RecommendationEngine, WeatherServiceClient, Open-Meteo, SavedLocation, видові правила, завдання, нагадування та рекомендації. Зовнішні виклики залишаються у погодному сервісі. Прогноз кешується за координатами на п’ять хвилин; одночасні запити до однакової локації об’єднуються. Помилка не кешується і не замінюється демонстраційною погодою.

Open-Meteo повертає поточні дані, добовий прогноз і погодинні температуру, опади, вологість, вітер, пориви та код погоди. Для перевірок температури використовуються добові мінімум/максимум, для вітру — максимум і пориви, а не лише середні значення. Часова зона — Europe/Kyiv. Час виконання CareTask не зберігається, тому прогноз оцінюється за календарну добу, без вигадування години роботи.

Прогноз попередньої календарної доби перед майбутнім поливом може спричинити попередження про перевірку ґрунту. Це **не виміряні опади**. Надійних фактичних спостережень за останні 24–48 годин поточний провайдер не надає: Forecast API `past_days` не є вимірюваннями, а ERA5/ERA5-Land у Historical Weather API мають затримку приблизно п’ять днів. Вологість і температура ґрунту не виводяться з погоди.

## Результати оцінювання

- Перенести пізніше: є обґрунтований конфлікт і придатна пізніша дата у прогнозі.
- Виконати раніше: мороз загрожує підтверджено чутливому врожаю; також можливе раніше висаджування перед перевищенням підтвердженої температурної межі.
- Попередження / перевірка: неповні дані, невідомі спосіб роботи чи експозиція, лише потенційний ризик або немає придатної дати.
- Залишити графік: погодної картки для завдання не створено. Загальний огляд рослини може залишатися.

## Вісім видів догляду

| Дія | Правила |
| --- | --- |
| Полив | Кількість опадів, а не ймовірність; прогноз на день поливу та попередню прогнозну добу; спека/сухість спонукають перевірити ґрунт і за потреби полити раніше. Дощ не означає достатнього зволоження. |
| Підживлення | Видові погодні межі; за значних опадів — можливий стік/змивання, за температурного стресу — обережність. Без способу внесення та інструкції добрива висновок залишається попередженням. |
| Обрізування | Значний дощ, явно заданий вітер/температура, чутливість виду до морозу; легкий дощ сам по собі не переносить завдання. Терміновість пояснюється, але не скасовує погодних застережень. |
| Пересаджування | Видові температурні межі, заморозки, спека, значний дощ. Стан ґрунту залишається невідомим. |
| Обробка | Нотатки відрізняють явно вказане обприскування від механічного видалення. Невідомий спосіб — попередження. Для препарату потрібна його інструкція; універсальний «безпечний вітер» чи інтервал дощу не стверджується. |
| Збір урожаю | Підтверджена текстом видових знань чутливість до сильних холодів дозволяє запропонувати збір до морозу. Дощ сам по собі не переносить збір. |
| Посів | Видові температурні межі та відомі застереження щодо морозу; значний дощ — перевірка ризику вимивання насіння. Температура ґрунту невідома. |
| Висаджування | Видові температурні/погодні межі, мороз, спека, вітер, значний дощ; обґрунтована інша дата або попередження про потребу захисту. |

Застосовність дій за категорією/видом збережено. Погодні правила не дозволяють заборонений догляд і не створюють непідтверджених інтервалів.

## Межі та невизначеність

Явні числові погодні межі SpeciesCareRule мають перевагу над загальними правилами. Пересаджування/посів/висаджування можуть використовувати наявні видові температурні знання; явна нічна температура в тексті висаджування також враховується.

Збережено наявний загальний поріг перенесення поливу/обрізування **понад 8 мм за добу**. Це обережне правило FloraWise, не твердження про насичення ґрунту чи універсальна агрономічна межа. Пороги перевірки (полив від 1 мм; значні опади від 8 мм; вітер/пориви від 8 м/с; мороз 0°C; екстремальна спека 35°C без видової межі) породжують попередження у відповідних діях, а не універсальний дозвіл чи заборону. Для відомого виду спека для перевірки поливу враховує його верхню оптимальну температуру + 5°C.

Приміщення і теплиця не прирівнюються до відкритої ділянки. Для балкона експозиція зараз не зберігається, тому вона невідома: немає автоматичного перенесення через дощ/вітер. Немає структурованих полів етикетки препарату, способу внесення добрива, стану ґрунту чи часу виконання; непідтверджені випадки залишаються попередженнями.

Кандидат дати має бути не в минулому, у доступному прогнозі, без порушення застосованих меж чи відомих застережень. Неповний температурний/вітровий прогноз не підтверджує придатність. Відсутність придатної дати не породжує вигаданої дати.

## Збереження і контроль користувача

Погодне обмеження показується перед звичайною терміновістю. Для простроченого зовнішнього завдання перевіряється прогноз на сьогодні, перш ніж радити виконання зараз. Формулу пріоритетів не переписано.

Кнопка «Перевірити рекомендації» аналізує рослини з активними завданнями пакетами до чотирьох запитів, використовує спільний кеш прогнозу, не змінює дат і не запускає фонових завдань. Часткова помилка пояснюється окремо.

Застосування вимагає підтвердження з рослиною, дією, обома датами і причиною. Перед мутацією повторно перевіряються активність, застосовність, знімок плану та саме поточне погодне рішення. Змінюється наявний CareTask і пов’язані нагадування; ID зберігаються. Лічильник відкладань збільшується лише для пізнішої дати. Початкова дата зберігається в застосованій рекомендації разом з appliedAt.

Повторна перевірка оновлює точний активний збіг, а інші активні поради для того самого завдання позначає заміненими. Записи не видаляються. Збереження набору серіалізується блокуванням рослини в транзакції. Повторне застосування заборонене. Після успіху інвалідуються деталі рослини, список рослин, Dashboard, завдання/календар, рекомендації, нагадування та статистика.

## Перевірки

- `test:rules`: детерміновані правила усіх восьми дій, середовища, попередній прогноз дощу, неповні дані, рання дата, відсутність альтернативи та погода перед терміновістю.
- `test:weather`: координати, одиниці, поточні/добові/погодинні дані, кеш, одночасні запити, помилка провайдера, лише явний mock.
- `test:categories`: застосовність і збереження обмежень.
- `test:custom-api`: ізольована схема БД; повторний аналіз, stale/refresh, ті самі ID, обидва напрями зміни дати, appliedAt, заборона повторного застосування, збереження після перезапуску сервера, правильні локації та відмова без провайдера.

Mock-погода використовується лише в явних детермінованих тестах та явно ввімкненому development-сценарії.
